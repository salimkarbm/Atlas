# ADR-0004 — Classify Data by Ownership Scope

## Status

**Accepted**

---

# Context

Atlas is a multi-tenant platform composed of bounded contexts, each responsible for managing business resources within clearly defined ownership boundaries.

Following the adoption of the Ownership Model (ADR-0003), every business resource has an explicit owner. However, ownership alone is insufficient to govern how information is managed throughout the platform.

The platform requires a consistent method for classifying data so that governance, lifecycle management, authorization, auditing, retention, and future architectural decisions can be applied uniformly across all business capabilities.

Data classification must therefore be based on the ownership of the information rather than its storage mechanism, implementation technology, or operational environment.

---

# Decision

Atlas classifies data according to its **ownership scope**.

Each data element belongs to exactly one ownership classification that reflects its governing authority within the platform.

The platform recognizes the following ownership scopes:

- **Platform Data** — Information owned and governed by the Atlas platform itself.
- **Tenant Data** — Information owned by a single tenant and isolated from all other tenants.
- **User Data** — Information owned by or directly associated with an individual user within the boundaries established by the platform and tenant.
- **System Data** — Operational information generated by the platform to support execution, monitoring, auditing, or internal processes.

Ownership scope is an architectural characteristic of the data and remains independent of storage technologies, deployment models, or infrastructure choices.

---

# Rationale

Classifying data by ownership scope provides a consistent governance model across the platform.

This approach:

- Aligns data governance with the platform's ownership model.
- Establishes a single architectural basis for lifecycle management.
- Enables consistent authorization decisions across bounded contexts.
- Supports auditing and compliance by identifying the governing owner of every data element.
- Allows implementation technologies to evolve without changing the classification model.

By classifying data according to ownership, Atlas ensures that governance decisions remain stable even as implementation details change.

---

# Consequences

The decision has the following architectural consequences.

## Positive

- Every data element has a clear governing owner.
- Data lifecycle policies can be applied consistently.
- Authorization models inherit ownership semantics.
- Audit and compliance capabilities can reason about information ownership.
- Business capabilities share a common data governance model.

## Trade-offs

- Data ownership must be identified during domain modeling.
- Shared or derived data requires explicit ownership definitions.
- Architectural reviews must verify data classification as part of capability design.
- Changes to ownership scope require deliberate architectural consideration.

These trade-offs are accepted because they improve consistency, governance, and long-term maintainability.

---

# Alternatives Considered

## Storage-Based Classification

Classify data according to where or how it is stored.

Rejected because storage technology is an implementation concern and does not determine governance responsibilities.

---

## Sensitivity-Based Classification

Classify data exclusively by confidentiality levels such as Public, Internal, Confidential, or Restricted.

Rejected because sensitivity describes how data should be protected, not who governs it. Sensitivity classifications may be introduced later as complementary security policies but do not replace ownership-based classification.

---

## Capability-Based Classification

Allow each bounded context to define its own classification model.

Rejected because inconsistent classification models weaken governance and reduce interoperability across the platform.

---

# Architectural Invariants

The following invariants result from this decision.

- Every data element has exactly one ownership scope.
- Ownership scope determines governance responsibility.
- Data classification is independent of storage technology.
- Data classification is independent of deployment architecture.
- Business capabilities inherit the platform's ownership-based classification model.
- Implementation must preserve ownership scope throughout the data lifecycle.

These invariants remain true regardless of implementation technology or infrastructure.
